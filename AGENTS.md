# AGENTS.md

`@xiaou66/picture-command` — the `u-upload` CLI for uploading images from the command line to the uTools 图床Plus (Picture Bed Plus) plugin. Talks to the running uTools plugin over a local IPC socket via `@xiaou66/interconnect-client`'s `ServiceClient` (RPC method `service.upload.file.sync`, service name `picture-bed-plus`, client id `command`). User-facing messages are in Chinese.

## Layout

- `src/u-upload.ts` — CLI entry (commander). Args: `<imagePaths...>`, `-u/--uploadId` (图床Plus 存储源 id), `-t/--timeout` (ms, default 15000). On "服务未启动" errors it opens the deep link `utools://图床 Plus/图床` via `open`/`start`/`xdg-open`. Exit code 0 if at least one upload succeeded, else 1.
- `src/uploadImage.ts` — core logic and published library API (`uploadImage`, `uploadImages`, `UploadResult`, `UploadOptions`). Uploads run sequentially; a new `ServiceClient` is created per image. The 4th constructor arg is `type() === 'Windows_NT'` (named-pipe vs unix socket).
- `bin/u-upload.cjs` — **generated by `pnpm build`** (copy of the dist bundle with shebang + chmod 755). It is git-tracked and is what npm publishes (`files: ["bin"]`); `dist/` is gitignored.
- `vite.config.ts` — CJS-only lib build, target node24, `commander` / `@xiaou66/interconnect-client` / `node:*` are externalized (do not bundle them), plus the `copy-bin-files` plugin. `engines.node` is `>=22.12.0` — the real runtime floor: commander 15 is ESM-only and needs `require(esm)` (Node 22.12.0+). The bin bundle inlines package.json (version + engines), so rebuild after changing either.

## Commands

- `pnpm build` — vite build → `dist/u-upload.cjs.js` + rolled-up `.d.ts`, then copies to `bin/u-upload.cjs`.
- `pnpm test` — smoke test only: `tsx src/u-upload.ts --help`. No real test framework, no lint config.
- `pnpm test:mac` / `test:win` — manual end-to-end upload of a hardcoded local image path; requires uTools with 图床Plus open.
- Typecheck: `npx tsc --noEmit` (tsconfig has `noEmit`, `strict`).
- Package manager is pnpm; publish via `npm publish` (`prepublishOnly` runs the build).

## Rules / gotchas

- After any change to `src/`, run `pnpm build` and commit the regenerated `bin/u-upload.cjs` — otherwise the published CLI and repo state drift from the source.
- The RPC contract (`picture-bed-plus` / `command` / `service.upload.file.sync`) must match the uTools 图床Plus plugin side; don't rename unilaterally.
- CLI version is read from `package.json` at runtime (`resolveJsonModule`); bump the version in `package.json`, not in source.
- ECONNREFUSED is treated as "uTools service not running" and mapped to a friendly Chinese error.
- Package is CommonJS (`type: commonjs`); keep the build output CJS.
